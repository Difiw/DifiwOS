# Архитектура Difiw Desktop (Difiw OS 0.4.0 Core)

Документ описывает то, что **реально реализовано** в 0.4.0. Ограничения и заделы на будущее — в разделе «Что не сделано».

## 1. Выбранный графический стек

X11 и Wayland-композиторы (и Qt/GTK) в Buildroot тянут много зависимостей и рассчитаны на GPU. В VirtualBox без
3D-ускорения это тяжело и рискованно. Поэтому в 0.4.0 используется **собственный минимальный стек**:

```
 Linux framebuffer (/dev/fb0, VESA 1024x768, 16/24/32 bpp)  +  evdev (/dev/input/event*)
          |
   difiw-desktop  (композитор + оболочка, программный рендеринг, один процесс от root)
          |  Unix-сокет SOCK_SEQPACKET /run/difiw/desktop.sock + shared memory (memfd)
   difiw-apps  (приложения: notes, calc, terminal, monitor, probe, worker) — каждое отдельным процессом
          |  и отдельным непривилегированным пользователем (UID 20001..)
```

Почему так: нет X/Wayland/Mesa, всё собирается тем же Buildroot-toolchain статически, поведение одинаково в QEMU и
VirtualBox, а границы между приложениями проходят по реальным процессам и UID (а не по «окнам внутри одного процесса»).
Цена: рисование на CPU, растровый шрифт 8x16 (кириллица + латиница), нет аппаратного ускорения и настоящего размытия.

## 2. Компоненты (src/difiw-desktop/)

| Файл | Роль |
|---|---|
| `tokens.hpp` | **единый набор дизайн-токенов** (цвета, радиусы, размеры, тайминги). См. DESIGN.md |
| `gfx.hpp/.cpp` | 2D-рендерер: поверхности, альфа-смешивание, скруглённые прямоугольники, тени, обводки со светом, шрифт PSF, обои, размытие, «стекло» |
| `proto.hpp` | протокол: фиксированные сообщения + передача fd (SCM_RIGHTS) |
| `client.hpp/.cpp` | библиотека для приложений: подключение по токену, окна, события |
| `tasks.hpp/.cpp` | **модель задач**: каталог приложений, экземпляры, службы, фоновые задачи, запуск с изоляцией, журнал |
| `desktop_core.cpp` | инициализация, главный цикл, framebuffer, evdev, клиенты, окна, управляющие команды |
| `desktop_input.cpp` | маршрутизация мыши/клавиатуры, раскладка, действия оболочки, всплывающие панели |
| `desktop_ui.cpp` | рисование: обои, окна, плавающая панель, кнопка D, меню, всплывающие панели, анимации |
| `apps.cpp` | тестовые приложения (один multi-call бинарник) |
| `difiwctl.cpp` | управляющий клиент (только root): запуск, состояние, снимки экрана, тесты |
| `desktop_main.cpp` | точка входа |

UI, модель задач, запуск, оконный менеджмент, разрешения и системные службы разделены по файлам; интерфейс **не**
разбирает вывод `ps`: данные берутся из `TaskModel`, а она читает `/proc/<pid>/{stat,statm}` для уже известных PID.

## 3. Модель задач

| Понятие | Что это в коде |
|---|---|
| приложение | `AppDef` из `/usr/share/difiw/apps/<app-id>.app` (стабильный `app-id`, uid, категория, права) |
| экземпляр | `Instance` (стабильный `instance-id` на время работы рабочего стола, pid, токен) |
| окно | `Window` (id, принадлежит экземпляру; у экземпляра их может быть несколько) |
| пользовательская задача | экземпляр, запущенный пользователем и имеющий окно: **только они** показываются в панели |
| фоновая задача | экземпляр без окна (процесс остаётся видимым в панели «Фоновые задачи») или системная служба |
| системная служба | `Service` из `/etc/difiw/services.d/*.svc` (имя процесса, критичность) |

Переход «окно закрыто, процесс жив» переносит экземпляр из панели в «Фоновые задачи», он не исчезает.
Завершение процесса убирает его значок/строку. Аварийное завершение → уведомление и запись в журнал.

## 4. Протокол приложение ↔ рабочий стол

Сообщение — структура фиксированного размера. Рабочий стол запускает приложение с переменными `DIFIW_TOKEN`
(секрет экземпляра), `DIFIW_SOCK`, `DIFIW_APP`. Приложение шлёт `HELLO(token)`; рабочий стол проверяет токен и
`SO_PEERCRED` (uid соединения должен совпадать с uid экземпляра). Затем:
`CREATE(w,h,title)+fd` → `CREATED(id)`; `COMMIT`, `TITLE`, `DESTROY`, `ATTACH(+fd)` после `CONFIGURE`; `REQUEST`
(выйти из рабочего стола, питание — только при наличии права в манифесте). События в приложение: мышь, клавиша
(код + UTF-8 текст с учётом раскладки), фокус, запрос закрытия, смена размера.

## 5. Оконный менеджер и оболочка

* создание/закрытие, перемещение (заголовок), изменение размера (края и углы, приложение пересоздаёт буфер),
  сворачивание, разворачивание, двойной щелчок по заголовку, z-order (raise при фокусе), Alt+Tab, Alt+F4;
* несколько окон одного приложения группируются в одном значке (число окон, список окон во всплывающей панели);
* плавающая нижняя капсула: слева запущенные пользователем приложения (стрелки и плавная прокрутка при нехватке места),
  по центру кнопка **D**, справа системная область (фоновые задачи, сеть, звук, батарея если есть, раскладка, часы, уведомления);
* всплывающие панели привязаны к источнику и считаются по границам экрана (`place_popup`); появляются из кнопки и
  возвращаются в неё;
* меню D: поиск (включая русские буквы), категории, сетка с постраничной прокруткой, профиль, питание.

## 6. Интеграция в сборку

* пакет Buildroot `buildroot-external/package/difiw-desktop` (статическая линковка, musl);
* реестр: `board/difiw/x86_64/overlay/usr/share/difiw/apps/*.app`, `.../etc/difiw/services.d/*.svc`;
* обои `assets/wallpaper.ppm.gz` → `/usr/share/difiw/wallpaper.ppm`, шрифт → `/usr/share/difiw/font.psf` (post-build);
* ядро: FB_VESA + fbcon + evdev; GRUB `vga=792` (1024x768); `mount -o remount,hidepid=2 /proc` в `inittab`;
* запуск: `screen` в Difiw Shell, либо автозапуск опцией ядра `difiw.desktop=1` (один раз за загрузку, на tty1);
  `screen --simple` — прежняя GUI в одном окне.

## 7. Что не сделано (честно)

* аппаратное ускорение, настоящее размытие в реальном времени (используется заранее размытая копия обоев);
* seccomp, cgroups, mount/network/pid namespaces, приватный `/tmp` (см. SECURITY.md);
* системный диалог выбора файлов, просмотр и отзыв разрешений, фоновые права;
* звук (в сборке нет аудиодрайверов), питание/батарея (в VM нет), многомониторность;
* перетаскивание значков/закрепление, окна на нескольких рабочих столах, анимация сворачивания окна;
* установка приложений (каталог фиксирован в образе).
