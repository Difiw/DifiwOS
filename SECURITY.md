# Безопасность и изоляция приложений (Difiw OS 0.5.6 Core)

Это **прототип**. Ниже — что реализовано и проверено, что нет. Заявлять больше не следует.

## Что реально работает

| Механизм | Как реализовано | Проверено |
|---|---|---|
| отдельный пользователь на приложение | рабочий стол (root) делает `setgroups(0)`, `setgid`, `setuid(20001+)`; проверка, что `setuid(0)` потом невозможен; `PR_SET_NO_NEW_PRIVS` | `Проверка дома`: `uid=20005`, «нет прав root» — PASS |
| «дом» приложения | `/homes/user/apps/<app-id>/`, владелец — пользователь приложения, режим `0700`; `/homes` и `/homes/user` — `0711` (нельзя перечислить) | чтение чужого дома → `Permission denied` |
| данные запуска | `/run/difiw/<app-id>/` (`0700`), `TMPDIR` внутри него | чтение `/run/difiw/notes/app.log` другим приложением → отказ |
| система не изменяется | файлы ОС принадлежат root, режим без записи для других | запись в `/usr` и `/etc` из приложения → `Permission denied` |
| чужие процессы не видны | `/proc` смонтирован с `hidepid=2`; окружение процесса 1 недоступно | чтение `/proc/1/environ` → отказ |
| подлинность клиента | токен экземпляра + `SO_PEERCRED` (uid) при подключении к рабочему столу | неверный токен → соединение закрывается, запись в журнале |
| права на запросы | в манифесте `perms=`; `REQUEST` без права → `S_DENIED` + запись в журнал | Терминал (имеет `desktop.quit,power`) работает, остальные получают отказ |
| критические процессы | `init`, `syslogd`, `difiw-desktop` помечены; завершение отклоняется (в UI кнопка недоступна, в `difiwctl` — «refused») | проверено |
| журнал | `/var/log/difiw-desktop.log`: запуск, завершение, закрытие, отказ в запросе, отказ завершить критический процесс; пароли и содержимое файлов не пишутся | проверено |

Все проверки приложения «Проверка дома» выполняются **настоящим процессом под настоящим UID** внутри ISO; результат
записывается в `/homes/user/apps/probe/probe-result.txt` и автоматически проверяется тестом
`tests/desktop_qemu.py`.

## Чего НЕТ (архитектурный задел, не заявляется как готовое)

* **seccomp, cgroups, лимиты ресурсов** — приложение может «съесть» память/CPU; fork-бомба не ограничена.
* **namespaces** (mount/pid/net/ipc): `/tmp` общий для всех пользователей; сеть не изолирована (если интерфейс
  появится, любое приложение сможет им пользоваться); `TMPDIR` лишь указывает на приватный каталог, но не принуждает.
* Приложение читает всё, что доступно «всем»: `/etc`, `/usr`, `/proc/<свой pid>` и т. д. «Режим чтения системных файлов»
  обеспечивается правами файлов, а не отдельным read-only монтированием (корень — запись в RAM, но только для root).
* **Нет системного диалога выбора файлов** и модели «выдать доступ к выбранному объекту»; нет интерфейса просмотра и
  отзыва разрешений; нет «фоновых прав».
* **Композитор — один процесс от root** и самое доверенное место: ошибка в нём — это повышение привилегий. Буферы клиентов
  ограничены 4096x4096 и проверяются по размеру файла, но фаззинг не проводился.
* Тесты клиентов в `difiw-apps` — прототипы; `Терминал` исполняет команды Difiw Shell **от своего пользователя**, а не root.
* Вход в систему без пароля (root в текстовой консоли) — осознанный выбор локального прототипа; изоляция защищает
  приложения друг от друга, а не систему от человека за консолью.
* Критические службы пока работают от root: отдельных системных учётных записей нет.
* Аудит безопасности и лицензий не проводился; публиковать образ в таком виде не следует.

## Как проверить самостоятельно

```
difiwctl launch probe        # в консоли root; затем
read /homes/user/apps/probe/probe-result.txt
difiwctl kill-task svc:init  # refused: critical system process
```
